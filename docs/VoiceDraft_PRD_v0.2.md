# VoiceDraft（暂定名）产品需求文档 v0.2

> 一个学习用户本人写作风格、辅助起草、经用户审核后通过 X 官方 API 发布的 Web SaaS。

> 现在的产品说明见 [VoiceDraft_PRD_v0.3.md](VoiceDraft_PRD_v0.3.md)。这份是最初规划，保留作历史记录。

**v0.2 相对 v0.1 的主要变化**
- 起草新增「快速模式」（整条候选 + 句级替换），逐句模式保留
- 新增「像不像」的衡量方法（盲测误判率），作为北极星指标
- 修改反馈即时生效（最近修改对直接作为示例），20 次总结保留
- 风格卡拆分为「代码统计指标」与「LLM 定性描述」；代表例句按话题检索
- 明确 X 加权字数规则（中文按 2 计）
- 新增：配图（模板卡片 / AI 生成图）、内容源（RSS、链接提取、TG、X 书签、X 大V 跟踪）、灵感池
- 新增：主动回复助手（扫描关注时间线 → 推送候选 → 用户一键确认后发出）
- 新增：自动发布与自动回复（批量审核 + 自动排期；用户显式开启的全自动发布 / 回复；不设条数上限，由 X 平台自身规则约束）
- 数据模型补齐版本关联、去重、用量、订阅、内容源相关表
- 里程碑调整为「先做起草原型验证核心体验」
- 补充隐私、版权、反洗稿要求

## 1. 产品定位

**一句话**：让 AI 写出来的推文像用户自己写的——因为风格来自用户本人的文字，每一句都由用户挑选或修改；默认由用户本人确认发布，也可以由用户设定规则后自动发布。

**核心差异**：市面上的 AI 推文工具大多「一键生成整条」，语气千篇一律。VoiceDraft 的做法是：
1. 从用户历史文字中提炼「风格卡」
2. 生成多个候选，用户在句子粒度上挑选 / 改写
3. 用户的每次修改立即影响后续生成，并定期沉淀进风格卡，越用越像本人

**目标用户**：个人创作者、独立开发者、小品牌主理人；以中文用户为主，后续支持英文。

**北极星指标**：风格盲测误判率（见 4.9）。辅助指标：从输入主题到复制 / 发布成品的中位时长、每条成品的平均修改次数。

## 2. 合规原则（硬性约束，开发必须遵守）

| 原则 | 具体要求 |
|---|---|
| 只走官方接口 | 发布、读取一律使用 X 官方 API + OAuth 2.0 用户授权。**禁止**浏览器自动化、模拟点击、模拟键盘输入；**禁止**使用第三方抓取服务或爬虫获取 X 内容。 |
| 本人账号 | 一个用户只能绑定自己授权的账号；不提供批量养号、账号矩阵功能。 |
| 发布由用户掌控 | 默认每条内容（含配图）发布前经过用户确认。用户可以**显式开启**自动发布（见 4.11），在其设定的来源、话题范围内自动发帖、自动回复，并可随时一键暂停。产品定位是 API 助手，不替 X 做风控：不设条数上限，账号行为由用户负责、由 X 平台规则约束；产品只保证调用方式合规（官方 API、不发重复内容、遇到限流即停）。**不做**：自动 @ 陌生人、自动私信、自动点赞 / 关注 / 转推。 |
| 不做检测规避 | 不做「去 AI 检测」「伪造浏览器指纹」「模拟打字轨迹」等功能。风格像本人，来源是用户自己的文字和修改，而非伪装。 |
| 数据归用户 | 用户上传的文字仅用于其本人风格卡；支持一键删除全部数据。 |
| 不洗稿 | 外部内容源只提供话题和观点启发，不提供「改写他人原文」功能；草稿与来源内容相似度过高时提醒用户。 |
| 尊重第三方 | 外部抓取遵守 robots.txt 与站点条款；只保存摘要与原文链接，不保存全文；他人的个人信息（如群聊发言者）不长期保存。 |

> 上线前需对照 X 当时有效的《开发者协议》《开发者政策》《自动化规则》《合成与篡改媒体政策》逐条复核。

## 3. 范围

### 3.1 MVP（P0）
1. 账号注册 / 登录（邮箱 + 密码，或 Google 登录）
2. 素材导入：粘贴文本、上传 .txt / .md / .csv、导入 X 官方存档文件（tweets.js）——**存档导入为主要素材来源**
3. 风格卡生成与编辑
4. 起草工作台：快速模式 + 逐句模式
5. 修改反馈（即时示例 + 定期总结）
6. 草稿箱（保存、编辑、删除）
7. 一键复制成品（按 X 加权规则计数）
8. 风格盲测

### 3.2 P1
1. X OAuth 绑定账号、定时发布（用户确认后进入队列）
2. 模板卡片配图（金句卡 / 数据卡 / 清单卡），随推文发布
3. 单篇链接 → 正文提取 → 要点 → 起草（素材采集）
4. 线程（Thread）拆分与排版
5. Stripe 订阅收费 + 用量额度
6. X 书签同步作为灵感来源；引用推文
7. （P1 后半段）RSS / Atom 订阅、公开 TG 频道、TG Bot 接入群聊 → 灵感池
8. 批量审核 + 自动排期：系统一次生成多条草稿，用户批量勾选通过后按排期自动发布
9. （P1 后半段）全自动发布：内容源 → 生成 → 发布，无需逐条确认（用户显式开启，见 4.11）
10. （P1 后半段）自动回复：用风格卡回复 @本人 和本人推文下的评论，可选「审核后发」或「全自动」（见 4.12）
11. （P1 后半段）主动回复助手：从关注时间线挑选值得回复的推文，生成候选推送到用户手机，用户一键确认后发出（见 4.13）

### 3.3 P2
1. AI 生成配图
2. 付费档：通过 X 官方 API 跟踪指定账号（大V）
3. 英文界面与英文风格卡

### 3.4 不做（Non-goals）
- 浏览器插件式模拟操作
- 多账号矩阵 / 批量养号
- 自动 @ 陌生人、自动私信、自动点赞 / 关注 / 转推
- 「AI 检测规避」类功能
- 爬取 X 网页，或使用第三方 X 数据抓取服务
- 使用用户个人 TG 账号登录（MTProto / Telethon / GramJS 等）读取群聊
- 全网爬取；「一键改写他人推文」

## 4. 功能详述

### 4.1 素材导入
- 支持粘贴、文件上传、X 存档导入
- 按内容哈希自动去重；过滤纯链接 / 纯转发 / 少于 10 字的内容
- 自动识别语言，中英文素材分别归入对应语言的风格卡
- 建议样本量：≥ 30 条；不足时提示「样本较少，风格卡准确度有限」
- 每条素材可手动删除或标记「不代表我」
- 为每条素材生成向量（pgvector），用于按话题检索例句

### 4.2 风格卡（Style Card）
风格卡分两部分，结构化存储，用户可直接编辑。

**A. 代码统计指标**（确定性计算，不调用 LLM，导入后即时更新）

| 字段 | 示例 |
|---|---|
| 句长分布 | 平均 15 字，P80 22 字 |
| 标点频率 | 感叹号 0.1 / 条；句号断句为主 |
| emoji 使用率 | 2% 的推文含 emoji |
| 高频词 / 口头禅 | 「说白了」「其实」（基于分词 + 词频，与通用语料对比） |
| 平均推文长度 | 加权字数 160 |
| 话题标签 / @ 使用习惯 | 几乎不用 # |

**B. LLM 定性描述**（低温度分析生成）

| 字段 | 示例 |
|---|---|
| 从不使用的词 | 「赋能」「深入探讨」「总而言之」 |
| 开头方式 | 常以结论 / 反问开头 |
| 观点表达 | 直接下判断，少用「可能」「或许」 |
| 幽默类型 | 冷幽默 / 自嘲 |
| 话题领域 | AI 工具、支付、创业 |

**代表例句**：不再固定 5–10 条，生成时按当前主题向量检索最相近的 5–8 条素材；用户可以「钉住」若干条始终带上。

风格卡有版本号，每次更新保留历史，可回滚。每种语言一张风格卡。

### 4.3 起草工作台（核心）

**输入**：主题 / 想表达的观点 / 参考素材（可选，可来自灵感池）

**快速模式（默认）**
1. 生成 3 条整条候选
2. 用户选一条；可对其中任意一句点「换这句」，得到 2–3 个替换候选
3. 可直接编辑任意文字，可锁定句子
4. 完成 → 预览

**逐句模式（长推 / 线程）**
1. 先给 2–3 个开头句候选
2. 用户选择、改写或「换一批」
3. 基于已确定的句子生成下一句的 2–3 个候选，循环直到「完成」

**通用交互**
- 每个候选旁有「改写」输入框
- 支持回退、整句锁定（锁定的句子不再被改动）
- 流式输出：候选逐个出现，而非等全部生成完
- 预览：按 X 加权规则计数（见 4.8）、可选的整体润色建议、可选配图（P1）
- 若本草稿来自外部内容源，预览时显示与来源的文本相似度；**≥ 67% 时**提示「建议加入你自己的观点」，并展示来源链接
- 相似度按文本重合度计算（字符 3-gram 重合比例，去除标点与空白后计算），不用语义向量：同一话题的语义相似度天然很高，用它会频繁误报

### 4.4 修改反馈（越用越像）
- 记录每次「候选原文 → 用户最终版本」的差异，关联到具体句子
- **即时生效**：最近 10 组修改对直接作为示例放进生成提示词（「以下是用户改写过的句子」）
- **定期沉淀**：每累计 20 次修改或用户手动触发，调用 LLM 总结规律（例如「用户总把『非常』删掉」「用户喜欢把长句拆成两句」），以「建议更新」形式展示，用户确认后写入风格卡新版本

### 4.5 草稿箱
- 列表：标题（首句）、更新时间、状态（草稿 / 已复制 / 已排期 / 已发布）、来源（手写 / 灵感池）
- 支持编辑、删除、复制

### 4.6 （P1）X 账号绑定与定时发布
- OAuth 2.0 授权，只申请必要权限：发布推文、上传媒体；书签同步需额外的书签读取权限，由用户单独开启
- 草稿 → 选择时间 → 二次确认 → 进入发布队列
- 配图通过 X 官方媒体上传接口上传，与推文一起发布
- 发布结果回写状态；失败时显示原因并允许重试
- Token 加密存储，支持随时解绑
- 读取用户本人历史推文需要付费 API 档，因此作为可选项，默认引导用户使用存档导入

### 4.7 （P1 / P2）配图

**模板卡片（P1，优先）**
- 卡片类型：金句卡、数据卡、清单卡
- 服务端用 Satori / @vercel/og 将 HTML 模板渲染为 PNG，零 LLM 成本，中文排版稳定
- 「视觉风格卡」：用户设定配色、字体、头像 / 水印，所有卡片统一
- 用户可编辑卡片上的文字后再生成

**AI 生成图（P2）**
- 流程：Claude 根据推文生成画面描述 → 调用图像模型 → 给 2–4 张候选 → 用户挑选
- 模型通过适配层接入，可选：OpenAI 图像接口、Google Imagen、Flux（经 Replicate / fal）；需要图中带文字时优先 Ideogram
- 按张计入用量额度
- 遵守 X 合成媒体政策，必要时提示用户标注 AI 生成

### 4.8 X 字数规则
- X 按加权计数：中日韩字符、emoji 计 2，拉丁字符计 1，链接固定按 23 计，上限 280（约 140 个汉字）
- 一律使用官方 twitter-text 库计算，前后端共用同一实现
- 超限时提示拆成线程

### 4.9 风格盲测
- 从用户真实推文中抽 5 条、生成同主题的 5 条，打乱后让用户挑出「哪些是 AI 写的」
- 记录误判率，按风格卡版本统计，作为北极星指标；也作为内测阶段的验收依据
- 用户可随时在设置页重新测试

### 4.10 内容源与灵感池（P1 起）

所有外部来源统一走一条流水线：

> 抓取 → 按 URL / 内容哈希去重 → 向量化并与用户关注话题做相关性打分 → Claude 提炼 3–5 个要点 → 进入「灵感池」→ 用户选一个要点 → 带入起草工作台作为「想表达的观点」

灵感池按相关性和时间排序，用户可收藏、忽略、按来源筛选。

**来源与接入方式**

| 来源 | 阶段 | 接入方式 | 说明 |
|---|---|---|---|
| 单篇链接 | P1 | 用户粘贴链接 → Readability / Jina Reader / Firecrawl 提取正文 | 仅处理用户主动提供的链接 |
| RSS / Atom | P1 后半段 | 定时轮询（Vercel Cron 或 QStash，每 15–30 分钟）；支持 WebSub 的源走推送 | 最稳定、最合规；也用于订阅大V的博客 / Newsletter / 播客 / YouTube |
| 平台官方 API | P1 后半段 | Hacker News、Reddit、YouTube、GitHub 等 | 按各平台条款与限额 |
| 公开 TG 频道 | P1 后半段 | 读取 t.me/s/频道名 的公开预览页，或经 RSSHub 转为 RSS | 只限公开频道 |
| TG 群聊 | P1 后半段 | **平台统一提供一个官方 Bot**（已关闭隐私模式）：用户在应用内生成绑定码 → 群管理员把 Bot 拉进群 → 在群里发送 `/bind 绑定码` 完成绑定；消息经 webhook 推送到后端，按群 ID 路由到对应用户；`/unbind` 或把 Bot 移出群即解绑 | 仅限用户本人管理或管理员同意的群；见下方隐私要求 |
| X 书签 | P1 | OAuth 拉取用户本人的书签 | 调用量小、成本低，推荐作为 X 侧主要灵感来源 |
| X 指定账号（大V） | P2 付费档 | X 官方 API 读取时间线，用 since_id 增量拉取，每 1–2 小时一次 | 每用户限 20 个左右账号；成本按「账号数 × 频率」计入定价；原推删除时同步删除；展示保留作者与链接 |

**TG 群聊的隐私要求**（GDPR 适用）
- 原始消息只作为短期缓存，保留 7 天后自动删除；长期只保存总结
- 入库前去除用户名、用户 ID 等可识别信息
- 每小时或每天生成一次「群里在聊什么」的总结
- 生成推文时不直接引用某个群成员的原话

**反洗稿**
- 外部来源（尤其是 X 大V）只输出「趋势和观点」汇总，不提供原文改写
- 起草时引导用户先写下自己的看法或角度
- 相似度检查见 4.3
- 想直接回应某条推文时，使用官方「引用推文」

### 4.11 （P1）自动发布

X 允许通过官方 API 定时、自动发布内容（例如定期分享文章），前提是遵守其《自动化规则》。本产品提供两档：

**档位 A：批量审核 + 自动排期（P1）**
- 系统根据灵感池或用户给的话题一次生成多条草稿（如一周 7–14 条）
- 用户在一个页面里批量浏览、编辑、勾选通过
- 通过的草稿按用户设定的时间表自动发布
- 每条都经过用户看过，风险最低，推荐作为默认的「省事」用法

**档位 B：全自动发布（P1 后半段，用户显式开启）**
- 用户设定规则：使用哪些内容源、哪些话题、发布时段、是否配图；每天条数和间隔为可选项，默认不限
- 系统按规则从内容源取选题 → 用风格卡生成 → 自动发布，无需逐条确认
- 开启时弹出说明：内容将不经确认直接发出，用户对发布内容负责

**基本保障（两档都适用，只管调用合规，不替 X 做风控）**
- 去重：与该账号近 30 天已发内容的文本相似度 ≥ 67% 时不发
- 来源：基于外部内容的推文必须附原文链接；与来源相似度 ≥ 67% 时不发（见 4.3）
- 内容检查：发布前做敏感内容与事实性风险筛查，不通过的转为待审核
- 透明：每天一封「今日自动发布」摘要；草稿箱里标注「自动发布」；可一键删除已发推文
- 熔断：一键暂停全部自动发布；X API 返回限流时按其要求退避重试，返回账号受限或异常时自动暂停并通知用户
- 不做：自动 @ 陌生人、自动私信、自动点赞 / 关注 / 转推
- 若账号主要由自动发布驱动，引导用户在 X 设置中为账号添加「自动化」标签

### 4.12 （P1 后半段）自动回复

发帖和回复是核心功能。回复内容同样基于风格卡生成，像本人说话。

**回复范围**
- @本人的推文
- 本人推文下的评论
- 不做未经确认就主动回复陌生人的推文（X《自动化规则》明确禁止未经请求的自动回复，违规可能导致平台的 API 权限被整体封禁，影响所有用户）。主动回复陌生人走「主动回复助手」，每条由用户确认后发出（见 4.13）

**两种模式**
- 审核后发：新提及 / 评论进入待回复队列，系统给出 2–3 个候选，用户选一个或改写后发出
- 全自动：系统直接用最合适的候选回复；用户可随时切回审核模式

**规则与保障**
- 拉取方式：官方 API 增量拉取提及与评论（since_id），按轮询或 X 提供的事件推送
- 用户可设跳过规则：广告 / 垃圾内容、攻击性内容、指定账号、含指定关键词的不回
- 同一条推文只回复一次；不对同一对话无限往复（默认同一对话最多连续回复 3 轮，用户可改）
- 回复记录全部保存在 ReplyLog，可一键删除已发回复
- 读取提及需要相应档位的 X API，成本计入定价（见第 8 节）

### 4.13 （P1 后半段）主动回复助手

目标：帮用户高效地参与别人的讨论，又保证每条回复都是本人决定发出的（属于辅助回复，不是自动回复）。

**流程**
1. 系统按用户设定的间隔（例如每 5 分钟）扫描用户**关注时间线**（X API 只提供按时间排序的关注时间线，拿不到「为你推荐」算法信息流）
2. 按用户关注的话题、推文热度、与用户领域的相关性打分，挑出值得回复的推文
3. 用风格卡生成 2–3 条回复候选
4. 推送到用户手机：通过平台 TG Bot（消息里带「发送 1 / 发送 2 / 改写 / 跳过」按钮）或网页推送
5. 用户点「发送」即通过官方 API 发出；点「改写」可编辑后再发；超时未处理的建议自动作废，不会发出

**规则**
- 每条回复必须由用户确认，没有「超时自动发送」
- 扫描间隔、话题、跳过规则（指定账号、敏感话题、关键词）由用户设定；不设条数上限
- 同一条推文只推送一次建议；用户已回复过的推文不再推送
- 每小时 / 每天汇总：推送了多少条建议、发出几条、跳过几条，帮助用户调整话题设置
- 用户在 TG 或网页上的选择与改写，同样作为修改反馈写入 EditLog（见 4.4）

### 5.3 Prompt 设计要点
- **系统提示**：注入风格卡（指标 + 定性描述）、检索出的代表例句、最近的修改对；明确「给出 N 个候选」「遵守禁用词」
- **提示词缓存**：风格卡和钉住的例句在同一用户的多次调用中不变，放在提示词前部并开启缓存，降低成本和延迟
- **上下文**：已确定的句子、用户主题、可选参考素材 / 灵感要点
- **输出格式**：使用结构化输出（JSON Schema），不靠提示词约束格式；流式时按候选逐个返回
- **温度**：候选生成偏高，以拉开差异；风格分析用低温度
- 所有 Prompt 放在独立文件中集中管理，并保留一组固定的评测样例，修改 Prompt 后先跑评测

## 9. 验收标准（MVP）
- [ ] 新用户导入 30 条素材后，统计指标即时生成，完整风格卡 1 分钟内生成
- [ ] 风格卡每个字段可编辑并保存，可查看历史版本并回滚
- [ ] 快速模式可完整走通：输入主题 → 选整条候选 → 替换 / 改写句子 → 完成 → 复制，中位时长 ≤ 2 分钟
- [ ] 逐句模式可完整走通：输入主题 → 逐句选择 / 改写 → 完成 → 复制
- [ ] 字数统计与 X 官方计数一致（含中文、emoji、链接用例）
- [ ] 用户改写过的句子，在下一次生成中能体现（示例被带入提示词）
- [ ] 修改 20 次后生成的风格更新建议，至少有一条能与具体修改记录对应
- [ ] 内测用户风格盲测的平均误判率 ≥ 30%（目标值，内测后校准）
- [ ] 删除账号后，数据库中该用户的所有数据被清除
- [ ] 全流程无任何浏览器自动化、模拟输入或第三方 X 抓取代码
